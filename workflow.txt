# 🏎️ Formula 1 Lakehouse & ML Analytics Project

## 📌 Project Overview

This project is an **end-to-end data engineering and machine learning pipeline** built on Formula 1 race data.
The goal is to demonstrate how raw, real-world data can be ingested, transformed, modeled, and served to generate **actionable insights** using modern data engineering and ML practices.

While Formula 1 is the domain, the focus of this project is on:

* scalable data pipelines
* clean data modeling
* reproducible machine learning
* explainable decision support systems

---

## 🎯 Objectives

* Build a **production-style data pipeline** using a lakehouse architecture
* Demonstrate **ML-driven insights**, not just dashboards
* Show **clear separation of concerns**: ingestion, transformation, modeling, serving
* Create **interpretable models** that support strategic decisions

---

## 🧠 MVP Machine Learning Use Cases

The MVP focuses on **three complementary ML use cases**:

### 1️⃣ Lap Time Prediction with Explainability

**Problem:**
Predict lap times using tyre, weather, and session context to establish a baseline pace model.

**Why it matters:**
This model serves as the foundation for all higher-level insights.

**ML Type:**
Regression

**Key Features:**

* Tyre compound
* Tyre life (laps on tyre)
* Track temperature
* Air temperature
* Session type (Qualifying/Race)
* Driver
* Track
* Lap number (fuel proxy)

**Outputs:**

* Predicted lap time
* Feature importance and SHAP explanations

---

### 2️⃣ Tyre Degradation Slope Modeling

**Problem:**
Quantify how tyre performance degrades over a stint under different conditions.

**Why it matters:**
Tyre degradation directly influences pit strategy and race outcomes.

**ML Type:**
Regression (stint-level modeling)

**Target Variable:**

* Pace degradation slope (seconds lost per lap within a stint)

**Key Dimensions:**

* Driver
* Tyre compound
* Track
* Track temperature
* Stint length

**Outputs:**

* Degradation curves
* Driver vs compound performance comparisons
* Best tyre selection insights per condition

---

### 3️⃣ Undercut / Overcut Success Probability

**Problem:**
Predict the probability that an undercut strategy will succeed.

**Why it matters:**
This models **decision-making under uncertainty**, a real-world ML use case.

**ML Type:**
Binary classification

**Label Definition:**

* Undercut is successful if:

  * Driver A pits
  * Driver B pits within N laps
  * Driver A finishes ahead of Driver B after both stops

**Key Features:**

* Tyre age before pit
* New tyre compound
* Track temperature
* Gap before pit stop
* Pit stop delta
* Traffic density proxy
* Remaining race laps

**Outputs:**

* Undercut success probability
* Feature-driven explanations

---

## 🏗️ Architecture Overview

This project follows a **Lakehouse Medallion Architecture**:

```
FastF1 API
   ↓
Bronze Layer (Raw Data)
   ↓
Silver Layer (Cleaned & Conformed)
   ↓
Gold Layer (Aggregated & ML-Ready)
   ↓
ML Models & Streamlit Dashboard
```

---

## 🗄️ Data Layers

### 🥉 Bronze Layer

* Raw data ingested from FastF1
* Minimal transformation
* Partitioned by season, event, and session
* Stored as Delta tables in Azure Data Lake

### 🥈 Silver Layer

* Cleaned and standardized datasets
* Consistent schemas and keys
* Fact and dimension tables
* Data quality checks applied

### 🥇 Gold Layer

* Aggregated, analytics-ready tables
* Optimized for ML training and dashboard queries
* Stable schemas aligned with business questions
